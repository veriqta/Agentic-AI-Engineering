# 06. Exercises

Use these tasks to apply the concepts together. They are not separate lessons for minor text changes. Keep your reference scripts intact and use clearly named copies for experiments.

## Exercise 1. Trace before execution

Write the five variable names in the briefing and identify the output line each supplies. Predict the complete report, then run the application and compare it with your prediction. Explain which statement prints text without interpolating a variable and why it needs no f prefix.

Expected outcome. You connect data to presentation without inventing a database, form or payment lookup. If a prediction differs, locate the responsible source statement rather than simply copying the observed output.

## Exercise 2. Diagnose a location problem

Start from the directory containing 09-source. Explain how the relative path to support_briefing.py changes if your shell enters 09-source itself. Do not move or delete the source. Use pwd and ls to verify your reasoning, then execute using the appropriate relative path. Return to the day directory afterward.

Expected outcome. You distinguish a file's location from the caller's current directory. You can also explain why the portability test uses an absolute script path.

## Exercise 3. Review an AI-generated claim

Consider this proposed explanation: The script verifies Sarah's enrollment and authorizes access because its output identifies the course.

Review the actual source. Identify the unsupported claims, cite the relevant assignments and limitation statement, and rewrite the explanation accurately. Do not add an API merely to make the inaccurate explanation appear true.

Expected outcome. Your corrected explanation identifies a simulated text briefing. It states that no enrollment or payment verification takes place.

## Exercise 4. Distinguish a valid run from correct behavior

In a separate copy, investigate what happens if an f prefix is removed from one formatted print statement. Predict the output first. Observe whether Python can finish successfully even though the field is wrong. Explain why a test comparing the output contract can catch a defect that exit status alone cannot.

Expected outcome. You identify the difference between successful execution and correct presentation. Restore the reference behavior in your working implementation. You do not need to repeat this exercise for every field.

## Exercise 5. Write a useful debugging record

Choose one actual path, quotation or variable-name failure encountered during the class. Record the command, observation, suspected cause, inspected source or location, correction and rerun result. If you have not encountered a failure, use the controlled assessment exercise rather than fabricating one.

Expected outcome. Another person can understand why the correction was justified. Your record keeps expected and actual output distinct and omits sensitive environment details.
