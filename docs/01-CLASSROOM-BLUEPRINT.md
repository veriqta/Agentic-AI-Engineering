# VERIQTA Agentic AI Engineering: Classroom Blueprint

## Your route through the course

You will study 13 modules across approximately 52 weeks. Each four-week module develops a substantial portfolio deliverable. Each week develops one working project increment. Each lesson teaches one bounded milestone that contributes to that project.

Begin at a module README, choose the current week, then follow the numbered lesson sequence. Complete each lesson's lab and understanding check before moving to the next major dependency. Use the weekly project to integrate what you have learned. Use the module assessment to demonstrate the complete four-week outcome.

## Consistent navigation

Module folders retain their existing names, such as module-01, to preserve the established roadmap. Within a module, use 01-week-01, 02-week-02, 03-week-03 and 04-week-04 as weeks are authored. Do not create empty future-week folders to imply completed teaching material. The final module project lives inside Week 04, not in a competing fifth module-level folder.

Within a week, 01-lessons contains the ordered lessons and 02-weekly-project contains the integrated project. Each lesson starts with a README and numbered notes, guided lab, walkthrough, knowledge check, answers, assessment, troubleshooting and exercises. Conventional README.md files remain so GitHub displays the start page automatically.

Number learning documents and navigation folders. Use conventional importable Python filenames, such as student_support.py and test_student_support.py, inside numbered source/test folders. Navigation numbering must not force you to learn dynamic module loading just to run ordinary tests.

## Teaching voice

Teaching pages address you directly as the person taking the course. They explain what you will build, why it matters and how to investigate failures. They do not refer to private conversations, an original student's screenshots, tutoring appointments or personal assessment status. Sarah is an example person; VERIQTA Academy is the recurring example organization.

## Every lesson

You receive a practical problem, clear objectives, necessary prerequisites, required environment and an achievable outcome. The notes introduce the concept through a concrete analogy before connecting it to code. The guided lab explains each command before execution, gives complete runnable code, predicts output and provides a meaningful checkpoint. The walkthrough explains important lines, variables, data flow and decisions. Knowledge checks have separate explanations. Assessment criteria require evidence and reasoning rather than script memorization.

## Pace and AI assistance

Plan roughly 60 minutes per lesson, with additional project and assessment time. A long reference chapter is not a single class to rush through. Group closely related input variations into automated tests. Use AI to draft, review and improve software, while you remain responsible for understanding dependencies, side effects, correctness and trust boundaries.

## Weekly and module projects

A weekly project integrates the week's lessons and includes requirements, architecture, setup, complete code, tests, failure investigation, evidence and limitations. Lesson milestones contribute to it rather than becoming disconnected minor projects. The Week 04 module project combines the four-week skills and has a separate assessment.

## Learning records and publication

Your own progress record distinguishes planned, in progress, executed, verified, assessed and completed. Public release status describes which course material is available and which reference implementation checks passed. Individual progress stays in your own record and is not embedded into public teaching pages.

Reference evidence records actual environment, commands, output, source version and limitations. Expected output is labeled expected. A publisher run is not proof that you completed an assessment. Output panels are labeled renderings with raw records; they are never presented as photographs of a terminal.

All course changes use a feature branch from latest main and a pull request. The owner reviews and merges. No direct main pushes, automatic merges, packages, releases or external deployments are part of classroom publication.

## Program promise

You will build progressively toward production engineering capabilities in Python, models, tools, state, retrieval, orchestration, MCP, multi-agent systems, security, evaluation and operations. Projects and assessments must demonstrate those capabilities. A 52-week course does not manufacture five to ten years of production experience or guarantee a senior job title.
