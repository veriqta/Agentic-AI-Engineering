# Your Classroom Learning Guide

You will learn through explanation, guided construction, investigation and assessment. AI can help generate an implementation, but your responsibility is to understand what it does and verify its behavior.

## Work through a lesson

1. Read the README to understand the outcome and required prior knowledge.
2. Study the instructor notes. Trace the real-world problem into the application design.
3. Read each lab command explanation before executing it. Predict the expected result.
4. Follow the implementation and code walkthrough together. Identify inputs, return values, side effects and failure paths.
5. Execute the lab and compare actual output with expectations. Investigate differences using the troubleshooting guide.
6. Attempt the knowledge check before opening the separate answers.
7. Complete the practical assessment and record evidence against its criteria.
8. Apply the milestone to the weekly project and continue only when essential understanding is established.

## Plan your time

Most classes target approximately 60 minutes. Reading, building, testing and project integration typically require six to ten hours per week, with flexibility for your starting point and schedule. Split a lesson across sessions when you need more investigation time. Do not rush a confusing boundary merely to match a calendar.

## Use AI critically

Ask for explanations, trace examples and possible failure cases. Review generated commands for file changes and network activity before running them. Review source, dependencies and tests against requirements. Ask why a proposed design is appropriate. Retain changes you can explain and verify; do not change test expectations simply to accept an incorrect implementation.

## Build a portfolio progressively

Each week has one meaningful project developed through lesson milestones. Each four-week module culminates in a larger deliverable. Present requirements, architecture, source, tests, actual outcomes, failures and limitations. Remove secrets and private infrastructure details from public evidence. Never claim simulated payment data establishes real payment authority.
