# 07. Weekly Assessment

## Implementation

Reproduce the toolkit from the guided lessons. Show complete source, a valid request, a controlled invalid request and the test suite. Explain the name/status path through parameters, local variables, returns and JSON.

## Diagnosis

Use the controlled regression in an isolated copy. Predict affected tests, inspect actual failure evidence, explain its cause and verify a restored passing suite. Do not change expected tests to hide the defect.

## Engineering judgment

Sarah uploads a receipt that an AI interprets as successful. The authoritative provider still reports pending. Explain the access decision, the source of truth, the next verification action and what you would communicate. Do not substitute model confidence for authorized evidence.

## Review criteria

You meet the requirements when you can reproduce the application, explain its responsibilities, distinguish valid refusal from malformed input, interpret test failures, verify a correction and respect the trust boundary. If any item is unclear, revise and gather evidence before marking it assessed. This reference supplies no individual grade.

## Record your progress

Use planned, in progress, executed, verified, assessed and completed in your own learning record. A publisher reference run is not your assessment. Completing this weekly project does not complete Module 01; the module's final integration assessment belongs in Week 04.
