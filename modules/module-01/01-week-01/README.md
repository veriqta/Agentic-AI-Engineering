# Week 01: Build Your First Student Support Toolkit

You will build a small VERIQTA Academy support application from an understandable first program to a tested command-line tool. You will learn each responsibility before integrating it. Your weekly project combines the lesson milestones into one reproducible result.

## Follow this sequence

| Order | Lesson | Your milestone |
|---|---|---|
| 01 | [Your first program](01-lessons/01-first-program/README.md) | Execute Python and explain its output |
| 02 | [Values and decisions](01-lessons/02-values-and-decisions/README.md) | Represent a payment decision explicitly |
| 03 | [Reusable functions](01-lessons/03-reusable-functions/README.md) | Separate checking from response generation |
| 04 | [Validation and controlled failure](01-lessons/04-validation/README.md) | Reject unusable input and normalize allowed variations |
| 05 | [A command-line application](01-lessons/05-command-line-application/README.md) | Add arguments, JSON, diagnostics and exit status |
| 06 | [Automated verification](01-lessons/06-automated-verification/README.md) | Test the functions and the CLI together |
| Project | [Student Support Response Toolkit](02-weekly-project/README.md) | Integrate, investigate a regression and present evidence |

Plan approximately 60 minutes per lesson plus project and assessment time, roughly six to ten hours depending on your starting point. No fixed time commitment is assumed. If a prerequisite is already established, inspect the reference and complete its practical check without repeating introductory execution.

## What you need

Use a Linux terminal, Python 3.12 or later and vi or another editor you can operate. Ubuntu is the reference platform. You do not need to purchase EC2, install third-party Python packages or supply API keys. The application uses simulated status information and never changes real course access.

## How to use the material

Read each lesson's notes, then perform its guided lab. Compare the actual output with the expected result and investigate differences. Follow the code walkthrough before attempting the knowledge check and practical assessment. Keep your progress in your own learning record. Do not infer understanding from code execution alone.

## Weekly completion criteria

You can trace the complete request, explain validation and exceptions, reproduce the application, run the suite, diagnose one controlled failure and explain the trust boundary for payment information. The reference implementation and evidence are provided for comparison, not as a pre-awarded pass.
