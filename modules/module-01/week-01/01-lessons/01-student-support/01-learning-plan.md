# 01. Learning Plan, Outcomes and Prerequisites

## The engineering problem

A support representative repeatedly answers whether a student can access a course. An unreliable script might approve malformed data, crash on missing input or mix logs into a response another program expects to parse. A dependable component should have an explicit input contract, predictable decisions, useful errors and tests that detect regressions.

The first application deliberately uses supplied payment labels. It teaches software foundations without hiding behavior behind a model or framework. A later project must replace that simulated source with authorized evidence before any real access decision.

## Outcomes and how they will be assessed

| Outcome | Demonstration |
|---|---|
| Read a command before execution | Identify executable, script path, options and arguments |
| Follow values through functions | Trace a spaced name and mixed-case payment label |
| Distinguish assignment from comparison | Explain what is stored and what is tested |
| Validate input deliberately | Reject a non-string, an empty value and unsupported status |
| Separate business result from process status | Explain why unpaid can exit successfully |
| Read and produce JSON | Explain the dictionary, serialization and parsing |
| Explain application boundaries | Show that no provider, identity or access grant is verified |
| Use automated checks | Run nine test methods and identify a failing assertion |
| Troubleshoot | Introduce a bounded regression in a copy, fix it and rerun |
| Document reproducible evidence | Record versions, exact commands, actual outputs and limitations |

## Before starting

Readers need permission to create files and run Python. The command guide introduces navigation, editor actions and command arguments. No previous conversation, university course, LLM account or paid service is required. The preserved introductory scripts explain printing and basic decisions for readers who need that foundation.

## Suggested sessions

Session A, approximately 60 minutes: read the support-desk scenario, inspect the environment, understand paths and vi, review the baseline, then build the source using the guided lab. Stop after one valid execution and explain where its values traveled.

Session B, approximately 60 minutes: revisit the source walkthrough, build the test suite, compare output streams and run the tests. Investigate a failure before continuing. Automated input variations are one testing activity.

Session C, approximately 60 minutes: complete the weekly project evidence bundle, perform a controlled debugging exercise, answer the knowledge check and complete the practical assessment. Reading may take longer; competence, not time spent, determines completion.

## What is included and what comes later

Included: Python values and strings, Booleans, functions, branches, sets, exceptions, command-line arguments, JSON, logging, tests, subprocesses and evidence. These concepts appear because the project needs them, not as isolated syntax drills.

Later: modules and package installation in greater depth, virtual environments with actual dependencies, persistent student data, HTTP integration, timeouts, credentials, LLM calls, tool schemas, orchestration, retrieval, deployment and operational monitoring. The roadmap preserves all 13 modules; no claim of senior competence is based on this first application.

## Completion rules

Planned means specified. In progress means active study or implementation. Executed means a command ran. Verified means the output and criteria were checked. Assessed means practical understanding was reviewed. Completed requires all required lesson criteria. Published means accepted material is available on main, not just on a feature branch.

A passing test suite is one verified milestone. The lesson also requires correct explanations, a debugging investigation and safe judgment about external payment evidence. A week requires its full project scope; a module requires four weeks of objectives and its separate integrated assessment.
