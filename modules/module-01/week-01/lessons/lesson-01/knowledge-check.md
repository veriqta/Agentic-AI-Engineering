# Knowledge Check

Answer using the application and practical scenarios. There is no requirement to memorize a complete script. Record answers before reading [instructor explanations](knowledge-check-answers.md).

1. Trace `normalize_text("  Sarah  ", "student_name")`. Which value enters each parameter, what does strip do, and what is returned?
2. Why must the type check happen before `.strip()`? What happens to None?
3. Why is unpaid a valid negative decision while unknown is invalid input?
4. Why can an unpaid request exit with code 0?
5. Why does importing student_support during testing not start argument parsing?
6. What problem occurs if diagnostic logs are mixed into stdout JSON?
7. What do the nine passing methods establish, and what remains unverified?
8. A receipt-reading AI reports paid, but the trusted payment provider reports pending. Should access be granted, and what should happen next?

## Review criteria

A sufficient answer follows the data and explains consequences. Accept practical reasoning rather than exact wording. Confusion about payment trust, return values, valid versus malformed input, or success output requires further teaching before lesson completion. Individual answers and private learner records do not belong in public course documentation.
