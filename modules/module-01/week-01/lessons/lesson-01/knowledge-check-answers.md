# Instructor Explanations

Read after attempting the [questions](knowledge-check.md).

1. value receives the spaced name and field_name receives the error label. strip removes outside whitespace. The function returns Sarah, and the caller may assign it to a different variable. Returning does not print.
2. None has no string strip method. The type check raises a controlled ValueError before that method is called.
3. Unpaid is recognized by the contract and produces False. Unknown is not recognized, so interpreting it as a normal status would conceal invalid data.
4. Code 0 reports successful request processing. It does not report approval. A valid request can have a negative business decision.
5. The `__name__ == "__main__"` guard is false during import. Function definitions are available without running main.
6. A JSON consumer may fail to parse output containing log lines. Logging to stderr keeps diagnostics separate.
7. They verify only the asserted behavior for supplied cases and environments. They do not establish production security, real payment verification, full coverage, learner understanding or module completion.
8. Do not grant access on the model's interpretation. Keep access pending, communicate that verification is pending, and reconcile the authenticated provider record through a bounded follow-up or human review. Match the transaction to the correct student and course and the required amount/currency before approval. Do not ask the model to override authoritative payment evidence.
